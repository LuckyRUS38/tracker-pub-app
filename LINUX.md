# Huly Desktop на Linux: Wayland, Arch и окружения

Что проверено и что нет. Код Linux-части (`src-tauri/src/linux.rs`, трей, подсказки) написан и протестирован только в части разбора файлов и ответов D-Bus (тесты проходят на Windows). На живом Wayland, GNOME, KDE, Sway и Hyprland приложение **не запускалось**, поэтому ниже описано поведение по коду и по известным особенностям WebKitGTK и трея. Если что-то не сработает, пришлите вывод `huly-desktop` из терминала.

## Установка на Arch

Есть три способа, от лучшего к худшему:

1. **Пакет pacman из релиза** (рекомендуется): собирается из `.deb` без компиляции.
   ```bash
   git clone https://github.com/LuckyRUS38/tracker-pub-app.git
   cd tracker-pub-app/arch && makepkg -si
   ```
   Перед первым запуском откройте страницу релиза и убедитесь, что имя файла `.deb` совпадает с `_asset` в `PKGBUILD` (GitHub заменяет пробелы точками). Обновление: поменять `pkgver` и повторить `makepkg -si`.
2. **AppImage**: `chmod +x Huly*.AppImage && ./Huly*.AppImage`. Только AppImage обновляет себя сам. На Arch AppImage иногда конфликтует со свежими Mesa и Wayland: если окно пустое, см. «Если что-то не так».
3. **`.deb` через `debtap`**: не нужен, пункт 1 делает то же самое.

Зависимости: `webkit2gtk-4.1 gtk3 libayatana-appindicator openssl xdotool`. Для уведомлений на Sway, Hyprland, i3 нужен демон уведомлений: `mako`, `dunst` или `swaync`. GNOME и KDE имеют свой.

## Трей и закрытие окна

Раньше закрытие окна всегда прятало его в трей. Если трея нет (чистый GNOME, панель без модуля трея), окно становилось недоступным, а при отсутствии библиотеки трея приложение могло не запуститься.

Теперь так:
- Перед созданием трея проверяется, установлена ли библиотека `libayatana-appindicator` (`ldconfig -p`). Без неё трей не создаётся, потому что в готовой сборке её отсутствие оборвало бы запуск. Ошибка создания трея тоже не останавливает приложение.
- На Linux проверяется, есть ли на шине D-Bus хост значков трея (`org.kde.StatusNotifierWatcher`). **Нет трея: закрытие окна завершает приложение**, а запуск с `--hidden` (автозапуск) показывает окно. При первом таком случае показывается одно пояснение.
- Принудительно: `HULY_CLOSE_TO_TRAY=1` (всегда прятать в трей) или `HULY_CLOSE_TO_TRAY=0` (всегда закрывать).

Где взять трей:
| Окружение | Что сделать |
|---|---|
| KDE Plasma | работает сразу |
| GNOME | расширение «AppIndicator and KStatusNotifierItem Support» |
| Sway, Hyprland, river и др. | включить модуль `tray` в панели (waybar: `"modules-right": ["tray"]`) |
| i3 / bspwm | панель с поддержкой трея (polybar, i3bar с tray_output) |

## Горячие клавиши и Wayland

В приложении есть глобальное сочетание **Ctrl+Alt+H**: показать окно или убрать его. Оно работает на X11 и в XWayland. Wayland-композиторы, как правило, не разрешают приложениям перехватывать клавиши глобально, и тогда сочетание не регистрируется (в терминале появится строка `global shortcut not registered`). Обходной путь: привяжите запуск `huly-desktop` на клавишу средствами композитора. Повторный запуск не открывает второе окно, а выводит уже открытое вперёд.

```ini
# Sway (~/.config/sway/config)
bindsym $mod+Alt+h exec huly-desktop
# Hyprland (~/.config/hypr/hyprland.conf)
bind = SUPER ALT, H, exec, huly-desktop
```

Остальные сочетания (G и буква для перехода, `?` для памятки) работают внутри окна и от композитора не зависят.

## Уведомления

Системные уведомления идут через D-Bus (`org.freedesktop.Notifications`). Если демона нет, при запуске показывается однократная подсказка. Проверка вручную:
```bash
notify-send "тест"                                   # должно появиться окошко
busctl --user list | grep -E 'Notifications|StatusNotifier'
```

## Настройки Wayland и WebKitGTK

Файл `~/.config/huly-desktop/linux.env` (или `$XDG_CONFIG_HOME/huly-desktop/linux.env`) читается при старте до создания окна. Удобно для ярлыков и автозапуска, где неудобно задавать переменные. Формат `KEY=VALUE`, комментарии `#`. Разрешены только переменные с префиксами `WEBKIT_`, `GDK_`, `GTK_`, `HULY_`, `LIBGL_`, `MESA_`, `__NV_`, `__GL_`, `WAYLAND_`. Если переменная уже задана в окружении, побеждает окружение.

```ini
# ~/.config/huly-desktop/linux.env
HULY_SAFE_RENDER=1        # программная композиция: пустое или мерцающее окно
HULY_X11=1                # запуск через XWayland вместо родного Wayland
#WEBKIT_DISABLE_COMPOSITING_MODE=1
#__NV_DISABLE_EXPLICIT_SYNC=1   # мерцание на NVIDIA 555+ под Wayland (проверяйте по ситуации)
```

По умолчанию отключён рендерер DMA-BUF (`WEBKIT_DISABLE_DMABUF_RENDERER=1`): частая причина лагов и пустых окон на Wayland, NVIDIA и некоторых Mesa. Если вам нужен он, задайте `WEBKIT_DISABLE_DMABUF_RENDERER=0` в окружении.

## Если что-то не так

| Симптом | Что попробовать |
|---|---|
| Пустое окно, мерцание | `HULY_SAFE_RENDER=1`; затем `HULY_X11=1` |
| Лаги, тормозит интерфейс | уже отключён DMA-BUF; проверьте, не включён ли «другие пространства» в трее (на Linux по умолчанию выключен: это отдельные тяжёлые процессы WebKit) |
| Нет значка в трее | см. таблицу выше; запустите `busctl --user list \| grep StatusNotifier` |
| Нет уведомлений | `notify-send тест`; установите демон (mako, dunst, swaync) |
| Файловые диалоги не открываются | `xdg-desktop-portal` и портал вашего окружения (`-gtk`, `-kde`, `-hyprland`, `-wlr`) |
| Окно не закрывается, а сворачивается (или наоборот) | `HULY_CLOSE_TO_TRAY=0` / `1` |

Запуск из терминала показывает сообщения приложения: `huly-desktop` (для AppImage: `./Huly*.AppImage`). Пришлите вывод, если нужна помощь.

## Обновления

- **AppImage** обновляется сам (при запуске и каждые 6 часов).
- **Пакет pacman / deb / rpm**: приложение само не обновляется и при ручной проверке напоминает об этом. Обновляйте менеджером пакетов (`makepkg -si` с новой `pkgver`).
